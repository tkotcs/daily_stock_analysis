After user Environment approval and material expiry/session validation, remote_execution_claim.py atomically CREATES annotated tag refs for the batch and each full request hash under refs/tags/dsa-mvp-consumed-v1/. Existing refs, conflicts, permissions failures, unknown write responses and partial claims stop the entire batch before model transport. No update, deletion, TTL, takeover, recovery or automatic retry is implemented. Reservations stay burned even if no model POST eventually occurs; they are execution tombstones, not evidence of supplier billing. Unknown outcomes remain possibly consumed. A new batch cannot reuse a globally reserved request hash.

The repository ruleset dsa-mvp-execution-claims must be active, cover the namespace, have no bypass actors and forbid update/deletion. Non-admin Actions tokens cannot read bypass_actors; they must receive current_user_can_bypass=never from GitHub (missing/other values stop). The owner audit separately verifies the empty bypass list. The existing local transport guard still caps sync/async sends to one per stock and the fixed loop caps three per batch. These records do not implement a monthly budget cap.
